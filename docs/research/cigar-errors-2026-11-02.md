# CIGAR support and error handling

Research date: 2026-11-02. Supporting evidence for standard-operation support (Q56) and error handling. IGV Desktop source inspection uses commit `f4b78d6412fa31eaca9b5bad7b3c35a8925828da`. [design.md](../design.md) is the authority for Bamdalf's requirements. No malformed-file experiment or inspection of the user's BAMs was performed.

## Standard operations are not errors

SAM defines nine CIGAR operations: `M I D N S H P = X`. An operation outside this set, malformed syntax, or a disagreement between a present `SEQ` length and the query-consuming CIGAR lengths is different from an unusual but valid operation. `SEQ=*` explicitly means sequence is unavailable; `CIGAR=*` similarly represents unavailable CIGAR information. Absence alone must not be described as corruption. [SAM v1.6 specification, §1.4](https://samtools.github.io/hts-specs/SAMv1.pdf#page=8)

IGV's alignment-block builder has handling for all nine standard operations: `M`, `=`, and `X` build aligned blocks; `I`, `D`, and `N` have separate branches; `S` follows the soft-clip display preference; `H` is skipped visually; and `P` accumulates padding for an insertion. This establishes explicit support paths, not a proof that every possible legal combination is rendered correctly. [Operation definitions](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L42-L50), [block construction](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L502-L626), [match predicate](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L1294-L1296)

## Tolerance in IGV's block-construction layer

- **Unavailable information:** `CIGAR=*` takes a fallback branch creating one block from the stored read length. With a CIGAR-derived block length but empty sequence, the block retains that length and stores an empty base array. These are handling paths, not validation of the record's other fields. [CIGAR fallback](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L488-L500), [empty sequence handling](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/AlignmentBlockImpl.java#L22-L33)
- **Local recovery:** exceptions while constructing an individual operation are logged and iteration continues. This does not establish that the resulting alignment remains complete or usable. The operation-list parser runs before that catch and can throw while parsing a missing or oversized integer length. [Parser invocation](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L488-L500), [per-operation catch](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L565-L630), [integer parsing](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L651-L675)
- **Unknown operators:** this internal string helper does not validate the operation alphabet, and the construction loop has no final unknown-operation error branch. That does not mean a file containing an unknown opcode will load: upstream decoding may reject it before this layer is reached. [String helper](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L651-L675), [construction branches](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/SAMAlignment.java#L569-L629)

## Reader and regional-load behavior

IGV configures HTSJDK with `ValidationStringency.SILENT`; this suppresses validation beyond minimum parsing, not every possible decoding error. In the pinned dependency, HTSJDK 6.0.0, CIGAR decoding still occurs, and unknown operation codes can throw. [Reader setting](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/reader/SamReaderPool.java#L81-L86), [dependency version](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/build.gradle#L106), [SILENT definition](https://github.com/samtools/htsjdk/blob/6.0.0/src/main/java/htsjdk/samtools/ValidationStringency.java#L3-L18), [decoding before optional validation](https://github.com/samtools/htsjdk/blob/6.0.0/src/main/java/htsjdk/samtools/BAMRecord.java#L271-L289), [unknown-code exceptions](https://github.com/samtools/htsjdk/blob/6.0.0/src/main/java/htsjdk/samtools/CigarOperator.java#L96-L147)

An exception escaping record construction or decoding is caught outside the loader's record loop: IGV reports/logs the error and stops that iteration. This is not a general skip-one-bad-record-and-continue policy. The loader returns its tile after the catch, and downstream code constructs an interval from it; this does not establish the previous-view restoration behavior accepted for Bamdalf in Q27. [Iterator wrapper](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/reader/BAMReader.java#L151-L166), [query and loop](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/AlignmentTileLoader.java#L138-L164), [catch, cleanup, and return](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/AlignmentTileLoader.java#L276-L314), [interval construction](https://github.com/igvteam/igv/blob/f4b78d6412fa31eaca9b5bad7b3c35a8925828da/src/main/java/org/igv/alignment/AlignmentDataManager.java#L326-L331)

These sources do not measure how frequently malformed CIGARs occur in real data. They establish that IGV supports the standard operations and has both tolerance and failure paths; they do not justify describing a strict fail-the-whole-region-and-restore rule as IGV's general policy. Standard-operation support and genuine decoding failures are distinct concerns.

## Design implication

Q56 adopted support for all nine standard operations on 2026-11-02. The historical blanket-failure proposal was not adopted, and this research does not select strict validation or IGV-style partial results. [design.md](../design.md) defines rendering, failed-load restoration (Q27), error presentation (Q57), and unresolved validation boundaries. The `=` sequence symbol is separate from the CIGAR `=` operation.
